## Итоговый вопрос
Процессору выгодно грузить блок, потому что кэш-линия — минимальная порция, которую он получает из памяти за раз (64 байта). При последовательном доступе следующие элементы лежат рядом: одна загрузка сразу даёт 16 значений int, и к медленной оперативной памяти ходить нужно в 16 раз реже. Поэтому кэш и существует — чтобы часто нужные данные были уже под рукой

## Контрольные вопросы
1. Чтобы не ждать медленную оперативную память: кэш хранит нужные данные рядом с процессором, и он работает быстрее

2. Кэш маленький и очень быстрый, стоит внутри процессора. Оперативная память большая, но медленнее

3. Блок данных, который процессор загружает из памяти за раз — обычно 64 байта

4. При последовательном доступе одна кэш-линия сразу даёт 16 соседних значений int. При большом шаге из линии используется только 1 значение из 16 — остальное впустую

5. Потому что время зависит от загрузки системы и других процессов Windows — точные миллисекунды каждый раз чуть разные, поэтому смотрят на общую закономерность

## Итоговый вывод
Эксперимент показал, что скорость работы зависит не только от количества операций, но и от того, как программа обращается к памяти. При последовательном доступе время было минимальным, а при увеличении шага время росло: до шага 16 — понемногу, после — в несколько раз. Причина в кэше: процессор загружает данные блоками по 64 байта, и при последовательном чтении один блок сразу даёт 16 соседних значений, а при большом шаге почти весь блок оказывается ненужным
